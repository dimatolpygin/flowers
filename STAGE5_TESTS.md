# Stage 5 — чек-лист проверки (SHOP_ADMIN)

## Подготовка
- Применена миграция `0002_add_operator_limit.sql`
- У тестового `shop_admin` магазин в статусе `active`
- Есть 2 Telegram-аккаунта для e2e:
  - аккаунт 1: `shop_admin`
  - аккаунт 2: `operator` (для перехода по инвайту)

## 1) /add_operator
Команда:
`/add_operator Иван`

Ожидание:
- Бот присылает deep-link: `https://t.me/<bot>?start=invite_<token>`
- При открытии ссылки со 2-го аккаунта:
  - создается пользователь `operator`
  - в `invite_tokens.used_at` появляется дата
  - `shop_admin` получает уведомление о подключении флориста

## 2) /operators
Команда:
`/operators`

Ожидание:
- Выводится список операторов магазина
- Для каждого отображается имя/username и число заказов

## 3) /remove_operator
Команда:
`/remove_operator`

Ожидание:
- Появляются inline-кнопки удаления + кнопка отмены
- Нажатие "Удалить ..." удаляет оператора
- Нажатие "Отмена" ничего не меняет

## 4) /my_plan
Команда:
`/my_plan`

Ожидание:
- Видно: тариф, лимиты, `resolution`, срок подписки

## 5) /my_stats
Команды:
- `/my_stats день`
- `/my_stats неделя`
- `/my_stats месяц`

Ожидание:
- Генерации: `used/limit`
- Кол-во перегенераций за период
- Дата истечения подписки
- Топ операторов

## 6) /my_template
Команда:
`/my_template`

Ожидание:
- Если логотипа нет: сообщение о необходимости загрузки
- Если логотип есть: бот показывает его и кнопку "Заменить"
- После "Заменить" и загрузки PNG:
  - обновляется `shops.logo_template_url`

## Негативные кейсы
1. Превышен лимит операторов:
   - `/add_operator ...` -> "Достигнут лимит операторов по тарифу."
2. Просроченный/использованный инвайт:
   - "Ссылка недействительна/истекла/уже использована."
3. Команды shop_admin запускает оператор:
   - "Нет прав для этой команды."

## Быстрая SQL-проверка (после теста)
Проверь:
- `users` (роль, shop_id, telegram_id)
- `invite_tokens` (`used_at`, `expires_at`)
- `shops` (`operators_limit`, `logo_template_url`)
- `orders`/`generation_log` (для статистики)
